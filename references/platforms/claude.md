# Claude 环境（Claude Code / Cowork / Claude.ai）

**特点：** 原生支持，就是原版 skill-creator 的设计目标环境。

## 跑测试
- spawn 子进程，用 `claude -p` 跑带技能 / 不带技能对比
- 用 `eval-viewer/generate_review.py` 生成评审页面
- Cowork / 无头环境加 `--static` 参数

## 优化描述
- 用 `scripts/run_loop.py` 自动跑优化循环
- 用当前会话的模型 ID 来做优化（从系统提示里拿）

## 交付
- 用 `scripts/package_skill.py` 打包成 `.skill` 文件
- 用 `present_files` 交付

## Claude.ai 专属说明（无浏览器、无子代理）
- **跑测试**：没有子代理就没有并行执行。每个测试用例，自己读了技能 SKILL.md 之后，按指令完成测试提示词。一次跑一个。不如独立子任务严谨（你自己写技能自己跑，自带完整上下文），但作为初步验证够用了——反正有人工评审环节兜底。跳过基线对比，直接用技能完成任务就行。
- **评审结果**：没法开浏览器的话，直接在对话里展示。每个测试用例把提示词和输出都展示出来。如果输出是文件，存到文件系统里告诉用户路径，让他自己去看。直接在对话里问："这个效果怎么样？要改什么吗？"
- **量化基准**：跳过——没有基线对比就没意义了，重点放在用户的定性反馈上。
- **迭代循环**：还是一样——改技能 → 重跑测试 → 要反馈——只是中间没有浏览器评审环节。
- **描述优化**：需要 `claude` CLI 工具（特别是 `claude -p`），只有 Claude Code 有。在 Claude.ai 上就跳过。
- **盲测对比**：需要子代理，跳过。
- **打包**：`package_skill.py` 脚本在任何有 Python 和文件系统的地方都能跑。在 Claude.ai 上也能跑，用户可以下载生成的 `.skill` 文件。

## Cowork 专属说明（有子代理、无显示器）
- 有子代理，所以主流程（spawn 并行测试、跑基线、打分等）都能用。但如果遇到严重的超时问题，可以把测试提示词串行跑而不是并行。
- 没有浏览器和显示器，生成 eval viewer 时用 `--static <输出路径>` 写一个独立 HTML 文件，然后给用户一个链接让他点开。
- **重要提醒**：Cowork 环境好像不太愿意在跑完测试后生成 eval viewer，所以再强调一遍：**无论你在 Cowork 还是 Claude Code，跑完测试后都必须生成 eval viewer 让用户先看，然后你自己再去评估输出、做修改。** 用 `generate_review.py`（不要自己写自定义 HTML）。
- **反馈读取**：因为没有运行中的服务器，viewer 的 "Submit All Reviews" 按钮会把 `feedback.json` 下载成文件。然后你从那里读（可能需要先请求访问权限）。
- **打包**：能用——`package_skill.py` 只需要 Python 和文件系统。
- **描述优化**（`run_loop.py` / `run_eval.py`）：在 Cowork 里应该也能跑，因为它通过子进程调 `claude -p`，不需要浏览器。但请等到技能完全做完、用户确认满意之后再跑。
