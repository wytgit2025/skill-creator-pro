# 结构化输出类技能只覆盖典型情况，漏了灰色地带

- 类别: other
- 出现次数: 1
- 涉及技能: [meeting-action-items]
- 现象: 写"会议纪要→三段式"技能时，只给了纯决策/纯待办/纯悬而未决三个典型类别和对应 examples。第一次拿一段真实讨论模拟就遇到："B 版留到下个迭代再议"——时间点（下个迭代）定了，但方案本身没定；"前端 10/15 撤出"是排期前提不是待办。模型靠临场判断把它塞进了某一段，规则没显式覆盖。
- 根因: 写分类/分段输出技能时，习惯只举"干净"的典型例子，没想跨类混合情况。结果边界靠模型每次临场发挥，输出不稳定。
- 对策: 造这类技能时，主动在设计阶段问一句："有没有一条信息同时跨两类？"把灰色情况的拆法写成显式规则，并在 examples 里专门放一个灰色用例（不是只放典型用例）。
- 状态: open
