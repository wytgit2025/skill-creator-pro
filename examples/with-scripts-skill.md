# 示例：带脚本的技能（scripts + evals）

> 这个示例展示一个确定性操作为主的技能：识别哪些动作该脚本化，以及怎么在正文里贴调用样例。
> 能力模块判断：scripts=✓（文件遍历、日期读取、目录创建、文件移动都是确定性操作），evals=✓（文件有没有被正确移动到对应日期文件夹是可客观验证的）。

---

## 用户原话

> "做个技能，把我下载文件夹里的照片按拍摄日期自动归档——2024年3月拍的就放到 ~/Pictures/2024-03/ 下面，不要按文件修改时间，要读 EXIF 里的拍摄时间。"

## 访谈摘要

| 问题 | 用户回答 |
|------|---------|
| 触发场景 | 用户说"整理照片""按日期归档照片""下载文件夹的照片太多了" |
| 输入 | 一个文件夹路径（默认 ~/Downloads），里面有 .jpg/.jpeg/.heic 文件 |
| 输出 | 照片被移动到 ~/Pictures/YYYY-MM/ 目录结构中；输出一份整理报告（移动了多少张、跳过了多少张、错误） |
| 有没有确定性动作？ | 有——遍历文件、读 EXIF、创建目录、移动文件，每次逻辑一样 |
| 需要测试吗？ | 需要——"文件有没有被移到正确目录"是可客观验证的 |

## 确定性动作识别清单

| 动作 | 每次是否一样 | 要不要脚本 |
|------|------------|-----------|
| 遍历指定文件夹下的图片文件 | ✅ 完全一样 | → 脚本 |
| 读取图片 EXIF 拍摄时间 | ✅ 完全一样 | → 脚本 |
| 按 YYYY-MM 创建目标目录 | ✅ 完全一样 | → 脚本 |
| 移动文件到目标目录 | ✅ 完全一样 | → 脚本 |
| 生成整理报告 | ✅ 完全一样 | → 脚本 |
| 判断"用户说的是不是照片归档任务" | ❌ 需要上下文 | → 正文指令 |

→ `--capabilities scripts,evals`

## SKILL.md 正文（关键部分）

```markdown
---
name: organizing-photos-by-date
description: "把文件夹里的照片按 EXIF 拍摄日期归档到 ~/Pictures/YYYY-MM/ 目录。当用户说'整理照片''按日期归档照片''下载文件夹的照片太多了''照片按月份分类'时使用。支持 .jpg/.jpeg/.heic 格式。"
---

# 照片按拍摄日期归档

把指定文件夹里的照片按 EXIF 拍摄日期移动到 ~/Pictures/YYYY-MM/ 目录。

## 怎么跑

用户给了文件夹路径后，执行：

```bash
python3 scripts/organize_photos.py --source <文件夹路径> --dest ~/Pictures
```

参数说明：
- `--source`：要整理的文件夹（默认 ~/Downloads）
- `--dest`：目标根目录（默认 ~/Pictures）

脚本会输出：移动了多少张、跳过了多少张（无 EXIF 或已存在）、错误列表。

## 注意事项

- **用 EXIF 拍摄时间，不用文件修改时间**——用户特意强调过，文件可能被编辑过。
- 没有 EXIF 信息的文件跳过并记录在报告里，不要瞎猜日期。
- 目标目录已有同名文件时跳过，不要覆盖。
```

## 设计决策注释

- **遍历/读EXIF/移动文件全部脚本化**：这些动作每次逻辑完全一样，不需要模型临场判断。模型只负责理解用户意图和解释脚本输出。
- **正文里贴了完整调用命令**：模型看到 `python3 scripts/organize_photos.py --source ...` 就知道怎么调，不用翻脚本源码。
- **evals 有客观断言**：跑一个测试文件夹，断言"2024-03-15 拍的照片出现在 ~/Pictures/2024-03/"——这是可以用脚本自动检查的。
- **description 列了文件格式**：`.jpg/.jpeg/.heic`——用户搜"HEIC 照片怎么整理"也能触发。
