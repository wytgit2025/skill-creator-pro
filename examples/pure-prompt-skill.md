# 示例：纯提示词技能（无 scripts / 无 evals）

> 这个示例展示一个纯判断型技能从用户需求到最终 SKILL.md 的完整过程。
> 能力模块判断：scripts=✗（每次都需要模型根据上下文自由改写），evals=✗（输出是主观文风，没有客观对错）。

---

## 用户原话

> "帮我做个技能，把我写的周报改成小红书风格——就是那种开头有emoji、分段短、每段一两句话、结尾有话题标签的感觉。我每周五写完周报直接丢给它就行。"

## 访谈摘要

| 问题 | 用户回答 |
|------|---------|
| 触发场景 | 用户说"改成小红书风格""周报发小红书"时 |
| 输入 | 一段周报原文（中文，可能 300-800 字） |
| 输出 | 小红书风格的文案，保留核心信息但语气更轻松 |
| 有没有确定性动作？ | 没有——每篇周报内容不同，改写需要理解上下文 |
| 需要测试吗？ | 不需要，"好不好看"是主观判断 |

## 能力模块判断

- **scripts**：不需要。改写风格需要模型理解内容和语气，不能脚本化。
- **evals**：不需要。文风好坏没有客观对错，人工看一眼就知道。
- **平台字段**：只在豆包工作用，不需要。

→ `--capabilities ""`（纯提示词技能）

## 最终产出的 SKILL.md

```markdown
---
name: rewriting-weekly-report-to-xiaohongshu
description: "把周报正文改写成小红书风格文案。当用户说'周报改小红书风格''把这段改成小红书体''发小红书用的周报'，或粘贴一段工作周报要求改成社交媒体风格时使用。"
---

# 周报 → 小红书风格改写

把用户给的周报原文改写成小红书风格的文案。

## 改写规则

1. **开头加一个贴切的 emoji**，和周报主题相关（加班用💻、增长用📈、团队活动用🎉）。
2. **拆成短段落**，每段 1-2 句话。原文如果是一大段，按主题拆成 3-5 个小段。
3. **语气轻松但不丢信息**：保留关键数据和结论，把"完成了XX项目上线"改成"终于把XX项目搞上线了🥹"。
4. **结尾加 3-5 个话题标签**，从内容里提取关键词（#周报 #工作总结 #职场日常 #产品经理）。
5. **不要编造原文里没有的成就**——只改写表达方式，不添加事实。

## 输入输出示例

输入：本周完成了用户增长方案V2版，新增3个渠道测试，下周开始投放。
输出：
📈 本周工作碎片

用户增长方案V2版终于定稿了！
新增了3个测试渠道，下周开跑。

等数据回来了再跟大家分享结果～

#周报 #用户增长 #工作总结
```

## 设计决策注释

- **description 列了用户原话**："周报改小红书风格""发小红书用的周报"——用户不会说"我要触发这个技能"，他只会说他想干嘛。
- **name 用动名词形式**：`rewriting-weekly-report-to-xiaohongshu`，一眼看出在做什么。
- **没有 scripts/**：改写需要理解上下文，脚本做不了。
- **没有 evals/**：文风好坏是主观的，跑断言没意义。
- **正文只放规则，不写废话**：模型知道什么是小红书风格，只告诉它"不能编造成就"这条红线。
